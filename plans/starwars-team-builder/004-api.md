# 004: API

## Context

Two route-handler families behind one Next.js app, both documented in `api.openapi.yaml`. Both surfaces live under the App Router as Route Handlers (`apps/platform/src/app/api/**/route.ts`), so handlers are plain async functions over Web `Request`/`Response`. Tests call them directly with `await GET(new Request(...))` and assert on the returned `Response`, no HTTP listener needed.

- The character routes (`GET /api/characters`, `GET /api/characters/{id}`) are thin route handlers that call a server-only `starwars-api` fetcher and downconvert the source-API payload to the `Character` shape from the contract. The browser never touches the source-API host.

- The team routes (`GET` and `POST /api/team`, `DELETE /api/team/{characterId}`) sit on top of three plain functions (`listTeamMembers`, `addTeamMember`, `removeTeamMember`) that hold every business rule (cap, duplicate, existence). The service functions share the same `starwars-api` fetcher so they can confirm a character exists before adding it.

`isDarkSide` is a stub returning `false`. Real rules land in Slice 006. Layering: `route → service function → repository → Drizzle`, each layer with one concern. The proxy bypasses the service since it has no business rules to enforce.

## Architectural ground rules (in addition to the repo-wide [`AGENTS.md`](../../AGENTS.md))

- **No classes.** `createError` builds a tagged `Error` with a `name: 'DomainError'` discriminator. `isDomainError(value)` is the type predicate. `mapError` reads `value.statusCode` and `value.code` off the tagged error.
- **No factory helpers.** Services are plain module-level functions, not constructor-style factories.
- **Object params for 2+ args.** Every function that takes two or more arguments destructures a single `<Fn>Params` object. Repositories take `{ teamId }` or `{ teamId, characterId }`.
- **`type` over `interface`** everywhere.
- **`type` aliases live in [`server/utils.ts`](../../apps/platform/src/server/utils.ts) and [`server/constants.ts`](../../apps/platform/src/server/constants.ts).** `errors`, `mapError`, and `toCharacter` collapse into one `server/utils.ts` rather than three single-purpose modules. Generic JS helpers (`firstOf`, `errorMessage`) live in [`lib/utils.ts`](../../apps/platform/src/lib/utils.ts).
- **Inbound shapes through Zod.** `characterIdSchema` and `addTeamMemberBodySchema` in [`server/schemas.ts`](../../apps/platform/src/server/schemas.ts). No hand-rolled `typeof` / `Number.isInteger` ladders.

## Goal (demoable outcome)

With Postgres up and migrated, `curl` hits every endpoint end-to-end.

- `GET /api/characters` returns the proxied `starwars-api` list, narrowed to the `Character` shape from the contract.
- `GET /api/characters/1` returns one character. `GET /api/characters/9999` returns `404 NOT_FOUND`.
- `GET /api/team` returns the team rows.
- `POST /api/team` with a fresh `characterId` returns `201` and persists. A duplicate `POST` returns `409 ALREADY_MEMBER`. A sixth `POST` returns `422 TEAM_FULL`. A `POST` with a known-bad `characterId` returns `404 NOT_FOUND`.
- `DELETE /api/team/{characterId}` returns `204` whether the row existed or not. The row is soft-deleted (`deletedAt = now()`), not removed from the table. It disappears from every read path.

Vitest integration tests import each Route Handler and invoke it directly with a `new Request(...)`, asserting on the returned `Response`. The upstream `starwars-api` is mocked at the network layer with [MSW](https://mswjs.io). `isDarkSide` is mocked with `vi.spyOn` under a `using` declaration.

## Prerequisites

- Slice 002 is done. The repositories, migration, and Docker Compose are in place.
- Planning Phase 1's [`plans/starwars-team-builder/contracts/api.openapi.yaml`](./contracts/api.openapi.yaml) is the source of truth for every path the browser calls (characters and team), every request/response shape, and the error-code enum.
- [`plans/starwars-team-builder/contracts/starwars.openapi.yaml`](./contracts/starwars.openapi.yaml) documents the source-API shape used server-side by the proxy fetcher.

## Steps

1. **Copy the contracts into the app.** Mirror `plans/starwars-team-builder/contracts/api.openapi.yaml` into `apps/platform/openapi/api.yaml`, and `plans/starwars-team-builder/contracts/starwars.openapi.yaml` into `apps/platform/openapi/starwars.yaml`. Both mirrors are what Slice 005's Kubb config will read. Prepend a one-line "Generated copy of <source>. Do not edit. Sync via cp." comment to each. Do not run Kubb in this slice.

2. **Tag the error codes in `constants.ts`.** Create `apps/platform/src/server/constants.ts`. It exports the `DomainErrorCode` union (`NOT_FOUND`, `ALREADY_MEMBER`, `TEAM_FULL`, `EVIL_FORBIDDEN`), an `ERRORS` lookup table that pairs each code with its HTTP status, and a `TEAM_CAP` constant. The table is frozen so codes stay literal at the call site. Adding a code touches this file plus the contract.

3. **Write `server/utils.ts`.** Three concerns in three labeled sections. The file replaces what would otherwise be three single-purpose modules.
   - **Errors.** `DomainError` is a tagged `Error` with a `name` discriminator and a `code` from the `ERRORS` table. `createError` builds it (shape mirrors Nuxt's `createError`: status code, code, message, optional `data`, optional `cause`). `isDomainError` is the type predicate. Call sites spread the matching `ERRORS` entry into `createError`. No named factory wrappers per code.
   - **Error mapping.** `mapError` is transport-agnostic. It returns a status plus a JSON-serializable body. Route handlers write the response themselves. Branches: a `DomainError` returns its documented status with a `{ code, message }` body. The `upstreamAsNotFound` flag (character proxy only) collapses raw errors to `404 NOT_FOUND` with a closed-enum body. Anything else returns `502` with a plain `{ message }` envelope and a `console.error` for operators.
   - **Character downconverter.** `toCharacter` picks contract fields off the upstream payload via an allow-list and `Object.fromEntries`. No per-field if-ladder. Absent optional fields stay absent on the output (not set to `undefined`).

4. **Stub `isDarkSide` and the `starwars-api` fetcher.**
   - `apps/platform/src/lib/darkSide.ts` exports a stub that always returns `false` with a TODO pointing at the Slice 006 rules in `data-model.md`.
   - `apps/platform/src/server/starwars-api.ts` exports the two fetchers. `fetchAllCharacters` throws on any non-200. `fetchCharacter` returns the parsed JSON on 200, `null` on 404, throws on any other status. The narrow `StarwarsApiCharacter` shape lives in the same file until Slice 005 generates it from `starwars.yaml`. This file is the **only** module that knows the upstream URL.

5. **Define the inbound schemas in `server/schemas.ts`.** One schema for the character id (positive integer, accepts Next's `string | string[]` query shape and coerces). One schema for the POST body (`{ characterId }` positive integer, mirroring `AddTeamMemberRequest`). Export an inferred type for the body.

6. **Convert the repositories to object params.** Every method on `teamMemberRepository` takes a single object argument (`teamId` alone for reads that don't need a character, or `teamId` plus `characterId` for everything else). Declare the two shared shapes once at the top of the file. Update the slice-002 repository test to pass the new shapes.

7. **Write the team service as three module-level functions** at `apps/platform/src/server/services/teamService.ts`. Each takes a single params object.
   - `listTeamMembers` delegates to the repository.
   - `addTeamMember` runs the rules in this order: existence (throw `NOT_FOUND` if upstream returns `null`), dark-side (throw `EVIL_FORBIDDEN` when `isDarkSide` returns true), duplicate (throw `ALREADY_MEMBER` when the repository finds an active row), cap (throw `TEAM_FULL` when the active count is at `TEAM_CAP`), insert.
   - `removeTeamMember` delegates the soft-delete to the repository. Safe to call twice. Ignores the boolean return.
   - **No SQL transaction.** The partial unique index on `(team_id, character_id) WHERE deleted_at IS NULL` catches the duplicate race. The cap race window is narrow and acceptable for the single-team scope. A code comment in `teamService.ts` documents the tradeoff.
   - **No class, no factory, no shared deps interface.** Route handlers resolve the default team themselves and pass the dependencies in line.

8. **Write the API routes under `apps/platform/src/app/api/`.** One `route.ts` per segment, exporting one async function per supported HTTP method. Next handles `405` plus the `Allow` header automatically based on which methods are exported.
   - `characters/route.ts` exports `GET` (`GET /api/characters`). Calls the upstream list fetcher, maps each entry through the downconverter, and wraps the body in a try/catch that funnels through `mapError` with the `upstreamAsNotFound` flag.
   - `characters/[id]/route.ts` exports `GET` (`GET /api/characters/{id}`). Reads `id` from `ctx.params` (await the promise), parses with the Zod schema. On parse failure or a `null` from the fetcher, throws a `NOT_FOUND` domain error. Same `upstreamAsNotFound` catch.
   - `team/route.ts` exports `GET` and `POST` (`GET` and `POST /api/team`). `GET` delegates to `listTeamMembers`. `POST` reads the body with `request.json().catch(() => undefined)`, validates with the Zod schema (returning a plain-`{ message }` `400` on failure) then delegates to `addTeamMember`.
   - `team/[characterId]/route.ts` exports `DELETE` (`DELETE /api/team/{characterId}`). Reads `characterId` from `ctx.params` and parses with the same schema. On parse failure, returns `204` (delete stays idempotent). Otherwise delegates to `removeTeamMember`.
   - Every handler carries a JSDoc block describing the behaviour in the house voice.

9. **Wire MSW at the test boundary.** `apps/platform/src/test/msw.ts` exports the shared `setupServer` instance and the upstream base URL. The setup file at `apps/platform/src/test/setup.ts` starts the server before all tests, resets handlers after each test, and closes it at the end of the suite. The `onUnhandledRequest` strategy is a function that bypasses `127.0.0.1` and `localhost` so the in-process test server can fetch itself, and errors on anything else so a forgotten upstream mock fails loudly. Allow MSW's build script in [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml).

10. **No bespoke test server.** Tests import the Route Handler exports directly and call them with `await GET(new Request('http://test/...'))`. Dynamic params pass through the second arg as `{ params: Promise.resolve({ id: '1' }) }`. The handler returns a `Response`, which tests assert on with `res.status`, `await res.json()`, and `res.headers.get(...)`.

11. **Entity fixtures.** `apps/platform/src/test/fixtures.ts` exports factories for each entity used in tests (team, team member, upstream character, contract character). Each takes a `Partial` overrides arg. Tests use the fixtures instead of restating hand-typed entity literals.

12. **Unit-test the service** at `apps/platform/src/server/services/teamService.test.ts`. Inline stubs per test, no shared repo helper. Cover the five `addTeamMember` branches in documented order, plus `listTeamMembers` and `removeTeamMember`. Assert the repository methods receive the expected object shape.

13. **Unit-test `utils.ts`** at `apps/platform/src/server/utils.test.ts`. One top-level describe for `utils` with child describes per concern: `createError`, the `ERRORS` table, `isDomainError`, `toCharacter`. Use `toMatchInlineSnapshot` for the downconverter's full-shape assertions and `toMatchObject` for partial domain-error checks.

14. **Integration-test the four route handlers** next to each `route.ts` file. Each test registers an MSW handler for the upstream call, invokes the exported method (`GET`, `POST`, `DELETE`) with a `new Request(...)`, and asserts on the returned `Response`'s status, body, and headers. Dynamic path params pass via the second-arg `{ params: Promise.resolve({...}) }`. The `isDarkSide` override uses `vi.spyOn` under a `using` declaration. The DB tombstone check for `DELETE` queries the table directly with Drizzle inside the test.

15. **Resolve the `400`-on-bad-body open item** in `plans/starwars-team-builder/research.md`. The decision: keep `400` (and `502`) implicit in `api.openapi.yaml`. Both stay as plain `{ message }` envelopes outside the closed `code` enum, matching the same operational-signal pattern. Slice 005 swaps the hand-rolled guard for the generated Zod parser but keeps the same envelope.

## Verification

1. `docker compose up -d postgres && turbo run db:migrate` from a clean state.
2. `pnpm dev` in one terminal. In another (live verification against the real `starwars-api`):
   - `curl -i http://localhost:3000/api/characters | head -n 1` → `HTTP/... 200`. The body length matches the upstream list.
   - `curl -i http://localhost:3000/api/characters/1` → `200`, JSON `Character` with only the contract's fields.
   - `curl -i http://localhost:3000/api/characters/9999` → `404`, body `{"code":"NOT_FOUND",...}`.
   - `curl -i http://localhost:3000/api/team` → `200`, `[]`.
   - `curl -i -X POST http://localhost:3000/api/team -H 'content-type: application/json' -d '{"characterId":1}'` → `201`, JSON `TeamMember`.
   - Repeat the previous command → `409`, body `{"code":"ALREADY_MEMBER", ...}`.
   - Loop ids 2..5 then `{"characterId":6}` → first four `201`, last `422 TEAM_FULL`.
   - `curl -i -X DELETE http://localhost:3000/api/team/1` → `204`.
   - `curl -i -X DELETE http://localhost:3000/api/team/9999` → `204`.
   - `curl -i -X POST http://localhost:3000/api/team -H 'content-type: application/json' -d '{}'` → `400 {"message":"Invalid request body"}`.
3. `pnpm test` is green. All five `addTeamMember` branches plus the route-level scenarios run against the real Postgres (PGlite in the test env) with the upstream `starwars-api` mocked by MSW.
4. `pnpm typecheck && pnpm exec oxlint -c oxlint.config.ts --disable-nested-config ./apps ./packages` are green across the workspace.
5. `turbo run build --filter=@whale/platform` lists all four routes under `Route (app)`: `/api/characters`, `/api/characters/[id]`, `/api/team`, `/api/team/[characterId]`.
