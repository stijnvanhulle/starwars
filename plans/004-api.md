# 004: API

## Context

Two route-handler families behind one Next.js app, both documented in `api.openapi.yaml`:

- **Character proxy**: `GET /api/characters` and `GET /api/characters/{id}` are thin route handlers that call a server-only `starwars-api` fetcher and downconvert the source-API payload to the `Character` shape from the contract. The browser never touches the source-API host.
- **Team**: `GET`, `POST /api/team` and `DELETE /api/team/{characterId}` on top of a `TeamService` that holds every business rule (cap, duplicate, existence). The service shares the same `starwars-api` fetcher to validate that a character exists before adding it.

`isDarkSide` is a stub returning `false`; real rules land in Slice 006. Layering: route → service → repository → Drizzle, each layer with one concern. The proxy bypasses the service since it has no business rules to enforce.

## Goal (demoable outcome)

With Postgres up and migrated, `curl` hits every endpoint end-to-end.
- `GET /api/characters` returns the proxied `starwars-api` list, narrowed to the `Character` shape from the contract.
- `GET /api/characters/1` returns one character; `GET /api/characters/9999` returns `404 NOT_FOUND`.
- `GET /api/team` returns the team rows.
- `POST /api/team` with a fresh `characterId` returns `201` and persists. A duplicate `POST` returns `409 ALREADY_MEMBER`. A sixth `POST` returns `422 TEAM_FULL`. A `POST` with a known-bad `characterId` returns `404 NOT_FOUND`.
- `DELETE /api/team/{characterId}` returns `204` whether the row existed or not.

Vitest integration tests run against the real Postgres and cover every branch, with `starwars-api` fetcher mocked at the module boundary.

## Prerequisites

- Slice 002 is done. The repository, migration, and Docker Compose are in place.
- Planning Phase 1's `plans/contracts/api.openapi.yaml` is the source of truth for every path the browser calls (characters and team), every request/response shape, and the error-code enum.
- `plans/contracts/starwars.openapi.yaml` documents the source-API shape used server-side by the proxy fetcher.

## Steps

1. **Copy the contracts into the app**. Copy `plans/contracts/api.openapi.yaml` to `apps/platform/openapi/api.yaml` and `plans/contracts/starwars.openapi.yaml` to `apps/platform/openapi/starwars.yaml`. Both mirrors are what Slice 005's `Kubb` config will read; checking them in now keeps the contracts close to the code. Add a one-line note at the top of each copy: `# Generated copy of plans/contracts/<file>. Do not edit; sync via cp.` Do not run `Kubb` in this slice.
2. **Define the typed error**. Create `apps/platform/src/server/errors.ts` with a `DomainError` class extending `Error`, carrying a `code: 'NOT_FOUND' | 'ALREADY_MEMBER' | 'TEAM_FULL' | 'EVIL_FORBIDDEN'` and an HTTP status. Export typed constructors: `notFound(msg)`, `alreadyMember(msg)`, `teamFull(msg)`, `evilForbidden(msg)`. These cover every code in the contract's `Error.code` enum. Source-API failures throw a plain `Error` and surface as `502` via `mapError` with a `{ message }` body; that fallback path is outside the documented enum and is meant for operational diagnostics, not for the UI to branch on.
3. **Stub `isDarkSide` and the `starwars-api` fetcher**. Create `apps/platform/src/lib/darkSide.ts` exporting `isDarkSide(character, masterNames): boolean` that returns `false` with a `// TODO(006): real rules, see data-model.md`. Create `apps/platform/src/server/starwars-api.ts` exporting two functions:
   - `fetchAllCharacters(): Promise<StarwarsApiCharacter[]>` that calls `https://akabab.github.io/starwars-api/api/all.json` and throws on any non-200.
   - `fetchCharacter(id: number): Promise<StarwarsApiCharacter | null>` that calls `https://akabab.github.io/starwars-api/api/id/${id}.json`, returns the parsed JSON on `200`, returns `null` on `404`, and throws on any other status.
   The `StarwarsApiCharacter` shape lives at `apps/platform/src/server/starwars-api.ts` as a narrow interface (`id, name, image?, height?, mass?, affiliations?, formerAffiliations?, masters?`) until Slice 005 generates the full type from `starwars.yaml`. This file is the **only** module that knows the `starwars-api` URL.
4. **Add the proxy downconverter** at `apps/platform/src/server/toCharacter.ts`. Pure function `toCharacter(`starwars-api`: StarwarsApiCharacter): Character` that strips the fields the contract's `Character` schema doesn't list and resolves ``starwars-api`.masters` (`starwars-api` ids) into the proxy's `masters: string[]` of names by joining against the cached `fetchAllCharacters()` list. The character routes call it; the team service does not (it keeps the `starwars-api` shape internally for `isDarkSide`).
5. **Write the character proxy routes** under `apps/platform/src/app/api/characters/`:
   - `route.ts` with `export async function GET()` that calls `fetchAllCharacters()`, maps with `toCharacter`, and returns the array. Wraps the body in the same try/catch + `mapError` as the team handlers.
   - `[id]/route.ts` with `export async function GET(_, { params })` that parses `id`, calls `fetchCharacter(id)`, returns `404 NOT_FOUND` (via `notFound(...)`) if `null`, otherwise `200` with `toCharacter(`starwars-api`)`.
   These handlers hold no business rules; they are pure plumbing. They do not touch the database, the service, or the repositories. Their request and response shapes are pinned to the contract's `listCharacters` and `getCharacter` operations.
6. **Write `TeamService`** at `apps/platform/src/server/services/teamService.ts`. Constructor takes the `TeamRepository`, the `TeamMemberRepository`, and the two helpers (`fetchCharacter`, `isDarkSide`) so the unit tests can swap them. The factory `createTeamService()` resolves the default team via `teamRepository.findDefault()` once and passes its `id` to the constructed service, which stores it as `private readonly teamId`. Methods:
   - `list(): Promise<TeamMember[]>`: delegates to `memberRepo.findAllByTeam(this.teamId)`.
   - `add(characterId: number): Promise<TeamMember>`: runs the rules in this order:
     1. `memberRepo.findByTeamAndCharacterId(this.teamId, characterId)` → if hit, throw `alreadyMember(...)`.
     2. `memberRepo.countByTeam(this.teamId)` → if ≥ 5, throw `teamFull(...)`.
     3. `fetchCharacter(characterId)` → if `null`, throw `notFound(...)`.
     4. `isDarkSide(character, new Map())` → if `true`, throw `evilForbidden(...)`. (Empty `masterNames` is fine; the stub ignores it.)
     5. `memberRepo.insert(this.teamId, characterId)` → return the row.
   - `remove(characterId: number): Promise<void>`: calls `memberRepo.deleteByTeamAndCharacterId(this.teamId, characterId)`. Idempotent. Ignores the boolean return.
   Order matters: duplicate-check before cap-check before existence-check matches the contract's status-code precedence and avoids leaking 5-member state to non-members. The `teamId` is captured once at service construction; introducing per-request team selection is a future change, not a refactor needed here.
7. **Write the team route handlers** under `apps/platform/src/app/api/team/`. Two files:
   - `route.ts` with `export async function GET()` and `export async function POST(req)`.
   - `[characterId]/route.ts` with `export async function DELETE(_, { params })`.
   Each handler is thin: parse input, instantiate the service from a tiny factory (`createTeamService()` in `src/server/services/teamService.ts`), call the method, return `NextResponse.json(...)` with the right status. Wrap each body in a single try/catch that calls `mapError(err)` (see step 8).
8. **Add the error mapper** at `apps/platform/src/server/mapError.ts`. Given an unknown thrown value, returns a `NextResponse` with the right status (`404`, `409`, `422`) and an `Error` body matching the contract. `starwars-api` proxy failures (any non-2xx that isn't `404` from `starwars-api.ts`) are mapped to `502` with a `{ message }` body, the `502` path is not in the contract's enum, so it does not carry a `code`. Unknown errors become a `500` with a generic body and are logged via `console.error`. This is the only place that knows about HTTP statuses; the service and the proxy throw plain errors and forget.
9. **Validate the POST body** with a hand-rolled guard (`isAddTeamMemberRequest(body)`) at the top of `POST`. A schema-driven approach lands in Slice 005 with the generated Zod. Reject with `400` and an `Error` body (`code: 'NOT_FOUND'` is wrong here, return a plain `{ message: 'Invalid request' }` and status `400`; the contract documents the four 4xx codes only for the matched paths). Document this gap in `plans/research.md`'s "Open items" section.
10. **Unit-test the service** next to it at `apps/platform/src/server/services/teamService.test.ts`. Inject fakes for both repositories, `fetchCharacter`, `isDarkSide`. The fake `TeamRepository.findDefault()` returns a fixed team id; assert every `memberRepo` call receives that id as the first argument. Cover the five branches of `add()` in the documented order plus the `list()` and `remove()` paths. No DB, no `fetch`.
11. **Unit-test the downconverter** next to it at `apps/platform/src/server/toCharacter.test.ts`. Cover: only contract fields survive, master ids resolve to names via the joined list, unresolved ids drop out silently, missing optional fields stay absent on the output.
12. **Integration-test the character proxy** next to the route at `apps/platform/src/app/api/characters/route.test.ts`. `vi.mock('@/server/starwars-api')` returns canned `starwars-api` payloads. Cover:
    - `GET /api/characters` → `200`, array shape matches the contract's `Character`, no `starwars-api`-only fields leaked.
    - `GET /api/characters/1` → `200`, narrow `Character`.
    - `GET /api/characters/9999` (mocked fetcher returns `null`) → `404 NOT_FOUND`.
    - `GET /api/characters` with the mocked fetcher throwing → `502` with a `{ message }` body (no `code`, since `502` is intentionally outside the contract's error enum).
13. **Integration-test the team route handlers** next to the routes at `apps/platform/src/app/api/team/route.test.ts` and `apps/platform/src/app/api/team/[characterId]/route.test.ts`. Boot the Next.js handlers directly via the App Router's testing surface (`import { GET, POST } from '@/app/api/team/route'`), pass real `Request` objects, assert on the `Response`. Reset the table between tests as in Slice 002. Cover:
   - `GET` on empty → `200`, `[]`.
   - `POST { characterId: 1 }` → `201`, body matches `TeamMember`.
   - `POST { characterId: 1 }` twice → `409 ALREADY_MEMBER`.
   - `POST` ids 1..5 then 6 → sixth returns `422 TEAM_FULL`.
   - `POST { characterId: 9999 }` (mocked `fetchCharacter` returns `null`) → `404 NOT_FOUND`.
   - `POST { characterId: 1 }` with `isDarkSide` mock returning `true` → `422 EVIL_FORBIDDEN`. (The stub returns false; the test patches the import to force the branch.)
   - `DELETE /api/team/1` after insert → `204`, row gone.
   - `DELETE /api/team/9999` on empty → `204`.
   - `POST {}` (missing `characterId`) → `400`.
   `fetchCharacter` is mocked via Vitest's `vi.mock('@/server/starwars-api')` so the integration test never hits the real `starwars-api`.
14. **Check the test script**. Slice 002's `pnpm test` already picks up every `*.test.ts` under `src/`, so the new colocated tests from this slice run automatically. No new scripts or configs are needed.
