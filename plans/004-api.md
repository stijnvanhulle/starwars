# 004 — API

## Context

Now that Slice 002 owns the table and the repository, this slice stands up the HTTP surface our team API contract describes. Three Next.js route handlers (`GET /api/team`, `POST /api/team`, `DELETE /api/team/{characterId}`) sit on top of a `TeamService` that holds every business rule. The service holds the rules; the repository holds the SQL; the route holds only parsing and error mapping. This is the layering rule from the Constitution Check, made real.

The `isDarkSide` predicate is left as a stub returning `false` with `TODO(006)`. Wiring real evil detection means fetching the character (and its masters) from `akabab`, which belongs with the rest of the `akabab` integration in Slice 005. The cap-of-5 guard, the existence check (404), the duplicate check (409), and the empty-error-mapping plumbing all land here so the contract is complete and the only `EVIL_FORBIDDEN` test is a unit test against the stub.

## Goal (demoable outcome)

With Postgres up and migrated, `curl` hits all three endpoints end-to-end. `GET /api/team` returns the seeded rows. `POST /api/team` with a fresh `characterId` returns `201` and persists. A duplicate `POST` returns `409 ALREADY_MEMBER`. A sixth `POST` returns `422 TEAM_FULL`. A `POST` with a known-bad `characterId` returns `404 NOT_FOUND`. `DELETE /api/team/{characterId}` returns `204` whether the row existed or not. Vitest integration tests run against the real Postgres and cover every branch.

## Prerequisites

- Slice 002 is done. The repository, migration, and Docker Compose are in place.
- Planning Phase 1's `plans/contracts/team.openapi.yaml` is the source of truth for paths, request shapes, response shapes, and error codes.

## Steps

1. **Copy the contract into the app**. Copy `plans/contracts/team.openapi.yaml` to `apps/platform/openapi/team.yaml`. This mirror is what Slice 005's `Kubb` config will read; checking it in now keeps the contract close to the code. Add a one-line note at the top of the copy: `# Generated copy of plans/contracts/team.openapi.yaml. Do not edit; sync via cp.` Do not run `Kubb` in this slice.
2. **Define the typed error**. Create `apps/platform/src/server/errors.ts` with a `DomainError` class extending `Error`, carrying a `code: 'NOT_FOUND' | 'ALREADY_MEMBER' | 'TEAM_FULL' | 'EVIL_FORBIDDEN'` and an HTTP status. Export typed constructors: `notFound(msg)`, `alreadyMember(msg)`, `teamFull(msg)`, `evilForbidden(msg)`. These are the only error shapes the route handlers translate into responses.
3. **Stub `isDarkSide` and the character fetch**. Create `apps/platform/src/lib/darkSide.ts` exporting `isDarkSide(character, masterNames): boolean` that returns `false` with a `// TODO(006): real rules, see data-model.md`. Create `apps/platform/src/server/akabab.ts` exporting `fetchCharacter(id: number): Promise<Character | null>` that calls `https://akabab.github.io/starwars-api/api/id/${id}.json` with `fetch`, returns the parsed JSON on `200`, returns `null` on `404`, and throws on any other status. The `Character` shape lives at `apps/platform/src/server/akabab.ts` as a narrow interface (`id, name, affiliations, masters`) until Slice 005 generates the full type.
4. **Write `TeamService`** at `apps/platform/src/server/services/teamService.ts`. Constructor takes the `TeamMemberRepository` and the two helpers (`fetchCharacter`, `isDarkSide`) so the unit tests can swap them. Methods:
   - `list(): Promise<TeamMember[]>` — delegates to `repo.findAll()`.
   - `add(characterId: number): Promise<TeamMember>` — runs the rules in this order:
     1. `repo.findByCharacterId(characterId)` → if hit, throw `alreadyMember(...)`.
     2. `repo.count()` → if ≥ 5, throw `teamFull(...)`.
     3. `fetchCharacter(characterId)` → if `null`, throw `notFound(...)`.
     4. `isDarkSide(character, new Map())` → if `true`, throw `evilForbidden(...)`. (Empty `masterNames` is fine; the stub ignores it.)
     5. `repo.insert(characterId)` → return the row.
   - `remove(characterId: number): Promise<void>` — calls `repo.deleteByCharacterId(characterId)`. Idempotent. Ignores the boolean return.
   Order matters: duplicate-check before cap-check before existence-check matches the contract's status-code precedence and avoids leaking 5-member state to non-members.
5. **Write the route handlers** under `apps/platform/src/app/api/team/`. Three files:
   - `route.ts` with `export async function GET()` and `export async function POST(req)`.
   - `[characterId]/route.ts` with `export async function DELETE(_, { params })`.
   Each handler is thin: parse input, instantiate the service from a tiny factory (`createTeamService()` in `src/server/services/teamService.ts`), call the method, return `NextResponse.json(...)` with the right status. Wrap each body in a single try/catch that calls `mapError(err)` (see step 6).
6. **Add the error mapper** at `apps/platform/src/server/mapError.ts`. Given an unknown thrown value, returns a `NextResponse` with the right status (`404`, `409`, `422`) and an `Error` body matching the contract. Unknown errors become a `500` with a generic body and are logged via `console.error`. This is the only place that knows about HTTP statuses; the service throws domain errors and forgets.
7. **Validate the POST body** with a hand-rolled guard (`isAddTeamMemberRequest(body)`) at the top of `POST`. A schema-driven approach lands in Slice 005 with the generated Zod. Reject with `400` and an `Error` body (`code: 'NOT_FOUND'` is wrong here — return a plain `{ message: 'Invalid request' }` and status `400`; the contract documents the four 4xx codes only for the matched paths). Document this gap in `plans/research.md`'s "Open items" section.
8. **Unit-test the service** at `apps/platform/tests/unit/teamService.test.ts`. Inject fakes for repo, `fetchCharacter`, `isDarkSide`. Cover the five branches of `add()` in the documented order plus the `list()` and `remove()` paths. No DB, no `fetch`.
9. **Integration-test the route handlers** at `apps/platform/tests/integration/teamApi.test.ts`. Boot the Next.js handlers directly via the App Router's testing surface (`import { GET, POST } from '@/app/api/team/route'`), pass real `Request` objects, assert on the `Response`. Reset the table between tests as in Slice 002. Cover:
   - `GET` on empty → `200`, `[]`.
   - `POST { characterId: 1 }` → `201`, body matches `TeamMember`.
   - `POST { characterId: 1 }` twice → `409 ALREADY_MEMBER`.
   - `POST` ids 1..5 then 6 → sixth returns `422 TEAM_FULL`.
   - `POST { characterId: 9999 }` (mocked `fetchCharacter` returns `null`) → `404 NOT_FOUND`.
   - `POST { characterId: 1 }` with `isDarkSide` mock returning `true` → `422 EVIL_FORBIDDEN`. (The stub returns false; the test patches the import to force the branch.)
   - `DELETE /api/team/1` after insert → `204`, row gone.
   - `DELETE /api/team/9999` on empty → `204`.
   - `POST {}` (missing `characterId`) → `400`.
   `fetchCharacter` is mocked via Vitest's `vi.mock('@/server/akabab')` so the integration test never hits the real `akabab`.
10. **Add the scripts**. In `apps/platform/package.json`, add `"test:unit": "vitest run --config ./vitest.unit.config.ts"` and ensure `test:integration` (from Slice 002) picks up the new `teamApi.test.ts`. If a unit config does not exist yet, create `apps/platform/vitest.unit.config.ts` mirroring the integration one but pointing at `tests/unit/**`.

## Verification

1. `docker compose up -d postgres && pnpm --filter platform db:migrate` from a clean state.
2. `pnpm --filter platform dev` in one terminal. In another:
   - `curl -i http://localhost:3000/api/team` → `200`, `[]`.
   - `curl -i -X POST http://localhost:3000/api/team -H 'content-type: application/json' -d '{"characterId":1}'` → `201`, JSON `TeamMember`.
   - Repeat the previous command → `409`, body `{"code":"ALREADY_MEMBER", ...}`.
   - Loop ids 2..5 then `{"characterId":6}` → first four `201`, last `422 TEAM_FULL`.
   - `curl -i -X DELETE http://localhost:3000/api/team/1` → `204`.
   - `curl -i -X DELETE http://localhost:3000/api/team/9999` → `204`.
   - `curl -i -X POST http://localhost:3000/api/team -d '{}'` → `400`.
3. `pnpm --filter platform test:unit` is green; covers all five `add()` branches.
4. `pnpm --filter platform test:integration` is green; the team API tests pass against the real Postgres.
5. `pnpm typecheck && pnpm lint` are green across the workspace.
6. `git grep -nE "from 'drizzle-orm'" apps/platform/src` still returns hits only under `src/db/**` and `src/server/repositories/**`. The route handlers and service never import Drizzle.
7. `git grep -nE "import.*akabab" apps/platform/src` returns hits only in `src/server/akabab.ts` and the unit/integration tests that mock it. The route handlers do not call `akabab` directly.
